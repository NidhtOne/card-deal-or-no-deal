## 一、项目概述

### 1.1 项目背景

将经典《一掷千金》（Deal or No Deal）玩法改编为纯娱乐性质的网页卡牌游戏：以随机奖金卡牌替代实体箱子，新增玩家还价、终局换牌、阶梯游戏税机制，配合五档段位场次、签到、任务、破产保护、成就等系统。游戏无任何充值、付费入口，全部资金为系统赠送与对局收益的虚拟游戏资金。

### 1.2 项目目标

1. 完整实现 V1.1 规则文档中的全部对局玩法与经济系统。
2. 提供用户注册、登录、个人信息管理与设置功能。
3. 提供角色系统：用户自行上传角色图片；对局加载页展示银行家角色与用户角色；对局进行中左侧为银行家角色、右侧为用户角色。
4. 提供背景音乐的播放、切换与设置能力。
5. 面向个人本地部署：单机/局域网可跑，一条命令启动，不依赖任何云服务。
6. 面向开源：代码结构清晰、配置外置、无隐私与密钥风险，他人克隆后可立即跑起来。

### 1.3 项目范围

| 类别 | 内容 |
| --- | --- |
| 本期包含 | 账号系统、角色/头像上传、五档对局完整流程、银行家报价与还价、终局换牌、阶梯计税、签到、每日任务、破产保护、对决历史与统计、成就系统、背景音乐、风险弹窗、本地一键部署 |
| 本期不包含 | 充值/提现/任何付费通道、多人联机、排行榜、移动端原生 App、中心化运营后台 |
| 开源后视情况 | 多语言、主题皮肤、Docker 镜像发布、社区 PR 功能 |

## 二、总体架构设计

### 2.1 架构形态

本地自托管的单体应用：前端静态资源由后端服务直接托管，数据库与文件全部落本地磁盘。

```
┌─────────────────────────────────────────────────────┐
│                  本地机器（Docker 或裸机）              │
│                                                     │
│   ┌──────────────┐         ┌─────────────────────┐  │
│   │  Web 前端     │  REST   │   后端服务 (Node)    │  │
│   │ React SPA     │ ◄────► │   业务逻辑 + 静态托管 │  │
│   └──────────────┘   WS    └──────────┬──────────┘  │
│                                       │             │
│                     ┌─────────────────┼───────────┐ │
│                     ▼                 ▼           ▼ │
│               ┌──────────┐    ┌────────────┐  ┌────────┐
│               │ SQLite   │    │ Redis      │  │ storage/│
│               │ data.db  │    │（可选，    │  │ 本地文件 │
│               │ (WAL)    │    │ 对局缓存）  │  │ 存储    │
│               └──────────┘    └────────────┘  └────────┘
└─────────────────────────────────────────────────────┘
```

### 2.2 技术选型

| 层 | 选型 | 理由（面向本地 + 开源） |
| --- | --- | --- |
| 前端 | React 18 + TypeScript + Vite + Tailwind CSS | 社区主流，贡献者门槛低，构建产物由后端托管 |
| 后端 | Node.js 20 + NestJS（或 Express，二选一，建议 NestJS 模块清晰） | 与前端同语言，开源仓库单一技术栈 |
| 数据库 | **SQLite（better-sqlite3，WAL 模式）为默认**；保留 MySQL 适配层（TypeORM/Prisma 切换） | 本地零依赖、免安装；单机并发足够；开源用户clone即跑 |
| 缓存/对局状态 | 进程内 Map + 定期落库为默认；Redis 作为可选开关 | 个人使用无需额外服务 |
| 实时通信 | WebSocket（socket.io）；也提供 REST 轮询兜底 | 掉线重连、超时提醒 |
| 文件存储 | 本地 `storage/` 目录（头像、角色图、音乐） | 零配置；README 中说明目录结构 |
| 认证 | JWT（Access + Refresh），密钥由本地环境变量生成 | 无需任何第三方账号体系 |
| 音频 | Howler.js | 前端统一管理 BGM/音效 |
| 部署 | Dockerfile + docker-compose.yml（前后端 + 数据卷）；同时支持裸机 `npm install && npm run dev` | 两种姿势都给出，README 写清 |

### 2.3 关键设计原则

1. **资金安全第一**：所有涉及游戏资金变动的操作（入场扣费、奖金发放、签到、任务、救助、成就奖励）在数据库事务内完成，并写入资金流水表。SQLite 下利用其单写者特性天然串行化写操作。
2. **对局状态服务端权威**：卡牌面额、底牌归属、银行家报价全部由服务端生成与判定，前端只负责展示与提交操作，杜绝篡改。
3. **对局进行中状态内存缓存 + 定期落库**：保证掉线重连可恢复，重启服务不丢局。
4. **幂等设计**：领奖、扣费、结算接口幂等，防重复请求导致资金重复变动。
5. **零硬编码密钥**：所有密钥/路径走 `.env`，仓库只提供 `.env.example`。

## 三、功能需求详述

### 3.1 账号系统

#### 3.1.1 注册

- 字段：用户名（唯一，4–16 位字母数字下划线）、密码（8–20 位，至少含字母与数字）、确认密码。
- 校验：用户名唯一性实时校验；密码强度校验。
- 注册成功后：自动创建用户档案、默认设置、初始资金账户（系统初始赠送，见 3.8），自动登录进入大厅。

> 本地自用场景不接入短信/邮件服务。找回密码提供两种方式：① 登录页「忘记密码」通过注册时填写的本地密保问题重置；② 仓库附带 `scripts/reset-password.js` 管理员脚本直接改库。开源版本中默认启用方式 ①，并在 README 注明本地性质。

#### 3.1.2 登录

- 用户名 + 密码登录；支持「记住我」（延长登录态有效期）。
- 连续失败 5 次锁定账号 15 分钟。
- 登录态采用 JWT（Access Token 2 小时 + Refresh Token 14 天），密钥读取 `JWT_SECRET` 环境变量；未配置时首次启动自动生成随机密钥并写入本地 `.env`（脚本完成，密钥永不出现在仓库中）。

#### 3.1.3 账号安全

- 修改密码（需验证原密码）。
- 账号注销：二次确认后删除个人数据；历史对局记录按设置匿名化保留或删除（默认直接删除，本地无合规负担）。

### 3.2 用户信息（个人中心）

- 头像：用户自行上传（JPG/PNG/WebP，≤5MB，建议 1:1，服务端压缩生成多尺寸缩略图）。
- 基础信息：用户名（注册后允许修改 1 次/30 天）、昵称、个性签名。
- 账户信息：当前游戏资金余额、今日签到状态、连续签到天数、今日破产救助已用次数。
- 数据概览：累计对局、总盈亏、胜率（与对决历史统计同源）。
- 我的角色：上传/更换/裁剪角色立绘（见 3.3）。

### 3.3 角色系统

游戏内有两个角色形象：**银行家**与**玩家角色**。

| 角色 | 图片来源 | 展示位置 |
| --- | --- | --- |
| 银行家 | 仓库内置若干默认银行家立绘（`assets/bankers/`），用户可在设置中挑选；也支持上传自定义图片覆盖 | 对局加载页、对局页左侧、报价弹窗头像 |
| 玩家角色 | **必须由用户自行上传**（未上传时使用系统占位剪影，并引导上传） | 对局加载页、对局页右侧、结算页 |

- 上传要求：JPG/PNG/WebP，≤5MB，建议竖版立绘（推荐 3:4），服务端统一压缩并提供裁剪界面。
- 一个用户可维护 1 张生效角色图（保留最近 3 张历史图供切换）。
- 图片校验：类型/大小白名单 + 服务端重编码（去 EXIF）。本地自用不接内容审核服务；开源版本在 README 中说明可自选接入审核 API。

### 3.4 对局加载页

点击进入对局后、对局画面出现前，展示加载页：

- 中央：银行家角色图（左）与用户角色图（右）相对而立，中间为「VS」或博弈主题动效。
- 展示本局信息：档位名称、入场门槛、单局最高奖金。
- 加载内容：卡牌池生成、资源预加载（角色图、音乐）。
- 提供「跳过」按钮（加载完成后自动进入对局）。
- 若用户未上传角色图，显示占位图并附「上传角色图」快捷入口。

### 3.6 游戏核心玩法（严格依据规则 V1.1）

#### 3.6.1 场次档位（固定，不可调整）

| 档位 | 入门门槛 | 单局最高奖金 | 解锁条件 |
| --- | --- | --- | --- |
| 取款机（新手保底档） | 388 | 3,888 | 默认解锁 |
| 入门档 | 2,000 | 10,000 | 持有资金 ≥ 2,000 |
| 标准档 | 20,000 | 100,000 | 持有资金 ≥ 20,000 |
| 进阶档 | 80,000 | 500,000 | 持有资金 ≥ 80,000 |
| 最高档（大神终极档） | 225,000 | 1,000,000 | 持有资金 ≥ 225,000 |

- 档位判定仅以对局开局瞬间账户资金为准，对局中资金变动不影响本局档位。
- 进入除取款机外的档位前弹出风险确认弹窗（可在设置中关闭，见 3.7）。

#### 3.6.2 卡牌池

- 每局 26 张卡牌，系统随机生成整套池，每张对应唯一固定奖金，金额不重复；总额无固定值。
- 奖金跨小额（0.01 / 0.1 / 1 / 10 / 50）到百万量级；档位越高，大额卡牌权重越高。
- 建议实现方式：为每个档位内置一套 26 档基础金额模板（含权重配置，做成配置文件 `config/tiers.json`），开局时在模板区间内按档位权重随机扰动生成，保证唯一性与档位上限约束。
- **面额清单开关**：开启时玩家可查看本局 26 张面额集合，已淘汰的实时划线，但不揭示位置对应关系；关闭则不展示。开关为全局设置项（见 3.7）。

#### 3.6.3 对局流程状态机

```
大厅 ──> 选择档位(扣入场费) ──> 加载页 ──> PICK_OWN_CARD(选1张底牌)
   │                                                  │
   │                                          FLIP_ROUND_N(按轮次翻牌)
   │                                                  │
   │                                          BANKER_OFFER(报价)
   │                                    ┌─────────────┼──────────────┐
   │                                 DEAL成交      COUNTER还价     NO_DEAL拒绝
   │                                    │              │               │
   │                              SETTLE结算      接受→SETTLE      剩余卡>2→下一轮
   │                                             拒绝→回到报价        │
   │                                                    剩余卡=2→FINAL_OFFER
   │                                                          │
   │                                            LAST_REFUSE→SWAP_DECISION(换牌/保留)
   │                                                          │
   └────────────────────────────── REVEAL开牌 → TAX计税 → SETTLE结算 → 存档
```

轮次固定：第 1 轮翻 6 张，第 2 轮 5 张，第 3 轮 4 张，第 4 轮 3 张，第 5 轮 2 张，第 6 轮起每轮 1 张，直至剩 2 张进入终局。

#### 3.6.4 银行家报价算法（服务端）

设当前剩余卡牌（含玩家底牌）金额集合为 R，期望值 EV = mean(R)：

1. 基础比例系数 k 按轮次递增收窄（前期低、后期高），并在区间内加入随机扰动，建议区间：前期 0.55–0.75，中期 0.65–0.85，终局 0.80–0.95。
2. 报价 Offer = min( EV × k , 档位单局最高奖金 )，向下取整，不为负数、不超过 EV。
3. 大额牌集中被淘汰时 EV 下降 → 报价自然走低；反之走高。算法本身即满足规则的公平性要求。
4. k 的区间与金额模板均放入配置文件，便于开源用户自行调整。

#### 3.6.5 还价机制

- 每轮限还价 1 次；还价失败保留原报价，不扣资金；输入非法值直接驳回且**不计入**本轮还价次数。
- 合法性校验：0 ≤ 还价金额 ≤ 档位最高奖金，且 ≥ 场上剩余卡牌中的最低面额；仅允许整数（或按档位最小精度）。
- 接受判定（建议实现，服务端概率模型）：
  - 还价 ≤ EV × 0.85：必定接受；
  - EV × 0.85 < 还价 ≤ EV：按线性递减概率接受，如 P = (EV − 还价) / (0.15 × EV) 映射到 90%→30%；
  - 还价 > EV：必定拒绝。
- 终局 2 张牌阶段同样适用每轮 1 次还价限制。

#### 3.6.6 终局换牌

- 玩家拒绝终局终极报价后，进入换牌决策：保留底牌 或 与最后 1 张公共卡牌互换（二选一）。
- 换牌后开牌结算，仅可取所选一张的金额作为税前奖金，不可相加。

#### 3.6.7 阶梯游戏税（服务端结算，公式固定）

- 单局盈利 = 税前奖金 − 入场门槛；盈利 ≤ 0 则记 0，不计税。
- 起征点 1,000：盈利 ≤ 1,000 免征。
- 应税金额 = 盈利 − 1,000，超额累进：

| 级数 | 应税区间（超出部分） | 税率 | 速算扣除数 |
| --- | --- | --- | --- |
| 1 | 0 – 5,000 | 3% | 0 |
| 2 | 5,000 – 20,000 | 10% | 350 |
| 3 | 20,000 – 100,000 | 20% | 2,350 |
| 4 | 100,000 – 500,000 | 28% | 10,350 |
| 5 | 500,000 以上 | 35% | 45,350 |

- 税费 = 应税金额 × 对应级税率 − 速算扣除数；盈亏不跨局抵扣。
- 实际到手 = 税前奖金 − 税费。

#### 3.6.8 对局异常处理

| 场景 | 处理 |
| --- | --- |
| 主动退出/掉线/页面崩溃 | 入场资金已扣不退；对局状态保留，可重连恢复（底牌、已淘汰牌、轮次、当前报价） |
| 5 分钟无操作 | 自动判 No Deal，自动走完剩余翻牌与终局流程，自动计税结算，写入历史 |
| 中途弃权 | 不提供手动弃权功能 |

超时计时以服务端为准，前端心跳/操作均上报重置计时器。

### 3.8 经济系统

#### 3.8.1 资金来源

系统初始赠送 + 签到 + 任务 + 破产救助 + 成就奖励 + 对局收益。无任何充值/付费/变现通道。初始赠送金额写入 `config/economy.json`（建议 10,000，可改）。

#### 3.8.2 每日签到

- 每日首次登录后可签到 1 次，不可补签；当日未签到则次日连续天数清零。
- 基础奖励 100，乘以连签倍数：第 1 天 ×1.0、第 2 天 ×1.2、第 3 天 ×1.5、第 4–6 天 ×1.8、第 7 天及以上 ×2.0（上限）。

#### 3.8.3 每日任务（每日 00:00 刷新）

| 任务 | 要求 | 奖励 |
| --- | --- | --- |
| 新手试水 | 参加取款机档 1 次 | 100 |
| 入门挑战 | 参加入门档 1 次 | 200 |
| 标准对决 | 参加标准档 1 次 | 500 |
| 进阶博弈 | 参加进阶档 1 次 | 1,000 |
| 巅峰之战 | 参加最高档 1 次 | 2,000 |
| 勤奋玩家 | 当日累计完成任意 3 局 | 300 |

- 开启对局即消耗入场资金即算「参加」；进度实时更新、自动判定；奖励需及时领取，刷新后失效。
- 所有奖励直接入账户，与普通资金完全通用。

#### 3.8.4 破产保护

- 触发：账户资金 < 388；仅大厅可申请，对局中不可。
- 每次救助 500，每日最多 3 次，00:00 重置；当日第 2、3 次申请时弹出提醒弹窗（如已开启）。
- 纯福利兜底，无需偿还。

#### 3.8.5 成就系统（可整体开关）

| 成就 | 条件 | 奖励 |
| --- | --- | --- |
| 初出茅庐 | 完成第一局任意档位 | 150 |

- 一次性解锁，达成自动弹窗，一键领取；成就页区分已解锁/未解锁。

### 3.9 背景音乐功能

- 曲目管理：仓库内置若干循环 BGM 曲目（`assets/music/`，大厅、对局、终局不同氛围），开源用户可直接替换目录内文件增删曲目。

- 顶部统计面板：累计对局数、累计盈利/亏损、总体胜率、单局最高盈利、各档位参与分布、累计交税总额。

## 七、核心算法与规则实现要点

1. **卡牌池生成**：按档位读取 `config/tiers.json` 金额模板与权重 → 加权随机抽取 26 个互不重复金额 → 打乱位置落库；全程服务端完成。
2. **报价**：EV = 剩余卡均值；Offer = min(EV × k(轮次), 档位上限)；k 的区间配置化，便于调整。
3. **还价判定**：按 3.6.5 的概率模型执行；所有随机判定服务端落库，保证可审计。
4. **计税**：统一走 `calcTax(profit)` 纯函数，附带单元测试覆盖规则文档中的两个示例（「盈利 20,000 → 应税 19,000 → 19,000 × 10% − 350 = 税 1,550；亏损局税 0」）。
5. **超时托管**：定时任务扫描 `timeout_deadline`（进程内定时器即可），触发自动 No Deal → 依次自动翻牌 → 若到终局自动拒绝并固定「保留底牌」→ 计税结算 → 写历史。
6. **任务进度**：对局开启（扣费成功）即记档位任务与勤奋玩家进度；结算时判断盈利类成就。
